# 위클리로그 · Weekly Log

개발팀의 Git 기록을 기능별 주간 업무로 정리하고, 미리보기에서 확인한 업무를 **기존 노션 부모 항목의 신규 하위 행**으로 등록하는 웹앱입니다. 이 저장소 루트가 프로젝트입니다. 하위에 `weekly-log` 폴더를 추가로 만들 필요가 없습니다.

## 빠르게 실행하기

Node.js **24 이상**과 Git이 필요합니다. 현재 개발 환경은 Node.js 26에서 검증했습니다.

```powershell
cd C:\workspace\codmos-creator\weekly-log
npm install
npm run dev
```

- 개발 화면: http://localhost:5173
- API 서버: http://127.0.0.1:4310
- 첫 화면에서 관리자 계정을 직접 만드세요. 기본 비밀번호는 없습니다.
- **설정 없이 데모 둘러보기**는 예시 데이터만 사용하며 Git 조회나 노션 저장을 수행하지 않습니다.

빌드한 앱은 한 서버로 실행할 수 있습니다.

```powershell
npm run build
npm start
```

이때 화면과 API 모두 http://localhost:4310 에서 제공됩니다. Windows에서는 `Start-WeeklyLog.ps1`로도 실행할 수 있습니다.

## 최초 설정

1. 첫 계정은 관리자로 생성됩니다. 이후 가입에는 관리자가 발급한 일회용 초대 코드가 필요합니다.
2. **내 설정**에서 Git 작성자 이름 또는 이메일, 노션 사용자 UUID를 입력합니다. 여러 Git 이름·이메일은 쉼표로 구분합니다.
3. 관리자가 **연결 설정**에서 프로젝트, 서버가 접근할 저장소 경로 또는 Bitbucket Cloud 저장소를 지정합니다.
4. 노션의 기존 데이터 소스, 정확한 부모 행, 기존 타임라인 보기와 속성 이름을 설정합니다. AI 탈출 코드의 경로와 ID는 현재 요청에 맞춘 초기값입니다. 다른 프로젝트는 별도로 추가하세요.
5. Notion 연결 토큰을 저장하고 대상 데이터베이스를 해당 연결에 공유합니다. 앱은 기존 페이지 수정 API를 호출하지 않습니다.
6. **저장된 연결 검사**를 실행합니다. 실제 하위 항목 관계와 시작·종료일 매핑을 확인하지 못하면 등록이 차단됩니다.
7. 팀원별 담당자 필터가 다르면 **내 설정 → 개인 타임라인 보기 ID**에서 본인이 사용하는 기존 보기를 지정합니다. 앱은 필터를 변경하지 않습니다.

### 구글 로그인

Google OAuth를 설정하면 로그인 화면에 **Google 계정으로 계속하기** 버튼이 표시됩니다. 첫 가입자는 관리자가 됩니다. 이후 가입은 기본적으로 기존 팀 초대 정책을 따릅니다. `GOOGLE_ALLOWED_DOMAIN`에 회사의 Google Workspace 도메인을 지정하면 해당 회사 계정은 초대코드 없이 멤버로 가입할 수 있습니다. 서버는 구글이 반환한 `hd` 값을 검사하며, 다른 회사 계정이나 개인 Gmail 계정은 거부합니다.

1. [Google Cloud Console](https://console.cloud.google.com/auth/clients)에서 OAuth 동의 화면을 구성하고 **웹 애플리케이션** 클라이언트를 만듭니다. 테스트 상태라면 로그인할 계정을 테스트 사용자로 등록합니다.
2. `.env`에 `GOOGLE_CLIENT_ID`와 `GOOGLE_CLIENT_SECRET`을 설정합니다. 회사 계정으로만 가입시키려면 `GOOGLE_ALLOWED_DOMAIN=your-company.example`도 설정합니다. 클라이언트 비밀키는 서버에서만 사용하며 저장소에 커밋하지 않습니다.
3. 승인된 리디렉션 URI를 **`APP_ORIGIN` 값 + `/api/auth/google/callback`**으로 등록합니다. 개발 화면에서는 `APP_ORIGIN=http://localhost:5173`과 `http://localhost:5173/api/auth/google/callback`을 사용합니다. 빌드한 앱을 로컬에서 실행하면 기본값은 `http://localhost:4310/api/auth/google/callback`입니다. 브라우저에서도 같은 호스트를 사용하세요.
4. 서버를 다시 시작하고 구글 로그인을 진행합니다. 배포 시에는 HTTPS 주소와 `COOKIE_SECURE=true`를 사용합니다.

기존 이메일·비밀번호 계정은 먼저 기존 방식으로 로그인한 뒤 **내 설정 → 구글 계정 연결**에서 같은 이메일의 구글 계정을 연결합니다. 이메일이 같다는 이유만으로 기존 계정과 자동 병합하지 않습니다. 연결한 뒤에는 구글 로그인으로 같은 계정을 사용할 수 있습니다. 구글 가입 계정에는 비밀번호를 만들지 않습니다.

구글에서 이름과 인증된 이메일을 확인한 뒤, 이메일 대신 구글 계정의 고유 식별자(`sub`)를 저장하여 이후 로그인에 사용합니다. 인증 요청은 브라우저 쿠키에 연결한 일회용 `state`와 PKCE로 보호하며 10분 뒤 만료됩니다. 구글 액세스 토큰과 클라이언트 비밀키는 브라우저로 전달하거나 데이터베이스에 저장하지 않습니다. 구현 기준은 [Google OpenID Connect 문서](https://developers.google.com/identity/openid-connect/openid-connect)입니다.

### 하위 항목 관계 확인

Notion의 하위 항목은 해당 보기의 `configuration.subtasks.property_id`와 연결된 자기 참조 관계로 검증합니다. 지정한 상위 관계 속성 또는 그 반대편 관계 속성이 이 값과 일치해야 합니다.

일부 타임라인은 공개 API 응답에 하위 항목 설정을 노출하지 않을 수 있습니다. 이 경우 **하위 항목 확인용 기존 표 보기 ID**에 같은 데이터 소스에서 하위 항목을 표시하는 기존 표 보기를 지정하세요. 앱은 새 보기를 만들거나 설정을 바꾸지 않으며, 확인할 수 없는 관계로 일반 행을 대신 만들지 않습니다.

### Bitbucket Cloud

- 저장소 읽기 권한이 있는 액세스 토큰: 토큰만 입력합니다.
- Atlassian API 토큰: 토큰과 계정 이메일을 함께 입력합니다.
- 로컬 모드는 서버에 있는 Git 저장소를 읽습니다. 원격 사용자의 PC 폴더를 웹브라우저에서 읽는 기능은 아닙니다.
- 정확한 작성일 필터를 위해 브랜치 이력을 최대 10,000개까지 검사합니다. 이 한도를 넘으면 부분 결과를 등록하지 않고 범위를 줄이거나 로컬 저장소를 사용하도록 안내합니다.

## 매주 사용하는 방법

1. **업무 분석**에서 프로젝트와 한 주 안의 조회 기간을 선택합니다. 기본값은 Asia/Seoul 기준 월요일부터 오늘까지이며, 주말에는 월요일부터 금요일까지입니다.
2. 변경 내용 규칙 분류 또는 Codex AI 분석을 선택합니다.
3. 실제 diff를 분석한 업무의 제목과 설명을 확인하고 편집합니다. 날짜는 각 업무에 포함된 금주 커밋의 첫·마지막 작성일로 고정됩니다.
4. 등록할 업무만 선택하고 **노션에 신규 등록**합니다.
5. **등록 이력**에서 Notion 링크를 열어 실제 일정 막대를 확인한 후 **일정 막대 확인 완료**를 누릅니다.

API만으로 픽셀 단위의 노션 화면을 확인했다고 주장하지 않습니다. 날짜·담당자·하위 관계를 재조회한 상태와 사용자가 실제 화면을 확인한 상태를 구분합니다.

## AI 분석

기본 규칙 분류는 Git 메시지·수정 경로·실제 diff를 바탕으로 소리, 키패드, 장면 전환, 화면 디자인, 서비스 연동 등의 목적을 분류합니다. 분류 결과는 등록 전 수정할 수 있습니다. AI 분석으로 표시하지 않습니다.

**Codex AI 분석**은 서버에 설치하고 로그인한 Codex CLI를 사용합니다. `codex exec`를 임시 디렉터리의 읽기 전용 샌드박스에서 실행하고, JSON 스키마로 업무 목록만 반환받습니다. 기존 사용자 설정을 불러오지 않으며 서비스 연결 토큰을 자식 프로세스 환경에 전달하지 않습니다. CLI가 없거나 인증되지 않으면 명확한 오류를 반환합니다. 실패한 AI 분석을 규칙 분석 결과로 가장하지 않습니다.

```powershell
codex login
```

PATH에 실행 파일이 없으면 `.env.example`을 `.env`로 복사하고 `CODEX_BIN`에 실행 파일의 절대 경로를 지정하세요. AI 분석은 서버에서 인증된 계정의 사용량을 소비하며 선택한 커밋의 메시지와 diff를 모델에 보냅니다. 규칙 분류에는 모델 호출이 없습니다.

## 고정 등록 규칙

- 기존 업무·날짜·설명·상태·보기·스키마를 수정하지 않습니다.
- 기능별 업무는 지정 부모의 직접 하위 행으로만 생성합니다. 본문 토글이나 추가 손자 행은 만들지 않습니다.
- 해당 주의 커밋 작성일 범위만 사용합니다. 기존 업무의 이전 주 날짜는 이어 붙이지 않습니다.
- 노션 업무명·설명에는 URL, Git 링크, 커밋 해시, 관련 커밋 목록을 넣을 수 없습니다. 커밋 해시는 앱 내부의 중복 방지와 분석 근거에만 사용합니다.
- 신규 상태는 `진행 중`이며, 커밋을 근거로 완료를 추정하지 않습니다.
- 같은 부모에 이미 처리한 커밋을 등록하지 않습니다. 동일 제목·동일 날짜의 기존 행도 재사용하거나 수정하지 않고 중복으로 제외합니다.
- Notion 저장 응답이 유실되면 **저장 여부 확인**으로 남기고 자동 재등록하지 않습니다. 재조회 기능으로 확인할 수 있습니다.
- 저장 완료와 검증 완료를 구분합니다. 일부 저장이 실패하면 성공한 항목은 유지하고 실패 상태를 개별 표시합니다.

## 팀에서 공유하기

처음에는 하나의 서버와 하나의 SQLite 데이터 디렉터리를 사용하는 사내 웹앱으로 운영하세요. 관리자 계정으로 팀원을 초대하면 각자 본인의 Git 작성자와 노션 담당자를 설정할 수 있습니다. 멤버는 프로젝트 경로·서비스 토큰을 변경하거나 다른 멤버의 분석 결과를 열 수 없습니다. 관리자는 팀의 등록 이력을 조회할 수 있습니다.

`.env.example`을 참고해 다음을 설정합니다.

```dotenv
HOST=0.0.0.0
PORT=4310
APP_ORIGIN=https://weekly-log.your-company.example
COOKIE_SECURE=true
DATA_DIR=./data
```

인터넷이나 사내망으로 공유할 때는 HTTPS 리버스 프록시 뒤에서 운영하고, 초기 관리자 계정을 먼저 생성하세요. 방화벽·DNS·TLS·실제 서버 배포는 자동 변경하지 않습니다. 기본 실행 주소는 로컬 전용입니다.

### 데이터와 비밀 정보

- `data/weekly-log.sqlite`: 계정, 프로젝트, 분석 결과, 등록 이력을 저장합니다.
- `data/.encryption-key`: 서비스 토큰 암호화 키입니다.
- 비밀번호는 개별 salt와 scrypt로 해시합니다. 세션은 HttpOnly·SameSite 쿠키를 사용합니다.
- 토큰은 AES-256-GCM으로 암호화해 서버에 보관하며, 조회 API로 원문을 반환하지 않습니다.
- `data/`와 `.env`는 Git에서 제외됩니다. 백업할 때 데이터베이스와 암호화 키를 함께 보관하고, 운영 서버의 파일 접근 권한을 제한하세요.
- 단일 서버 프로세스를 기준으로 합니다. 여러 서버 인스턴스로 확장할 때는 중앙 DB와 작업 큐로 전환해야 합니다.
- 예약 실행과 비밀번호 재설정 이메일은 이 버전에 포함하지 않습니다.

## 구성

- `src/`: React + TypeScript 화면
- `server/`: Express API, Git 분석, Codex CLI 연동, Notion 연결, SQLite
- `tests/`: Node.js 테스트
- `scripts/dev.mjs`: 개발 서버 실행
